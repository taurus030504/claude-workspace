# 문영일보 실시간 댓글 설계 (파이어베이스) — 초안 10-09

> 상태: **설계 초안, 구현 전.** 교사 결정 5가지(맨 아래)와 0단계 확인이 끝나야 구현을 시작한다.
> 이 문서는 다음 세션이 이어받을 수 있게 남기는 것. 결정이 나면 작업노트 "결정" 표로 옮긴다.

## 0. 목표와 범위

- 같은 반 학생이 쓴 댓글, 답글, 추천과 반대, 신고가 **서로의 화면에 1~2초 안에** 보인다.
- 교사가 턴, 반응 설정, 블라인드와 삭제를 한 곳에서 바꾸면 **새로고침 없이** 모든 화면에 반영된다.
- 시드 기사와 시드 댓글은 지금처럼 페이지 안 데이터(`site-data`)에 둔다. 파이어베이스에는 **학생이 만든 것만** 올린다.
- 연결이 안 되면 지금 방식(각자 브라우저 저장)으로 저절로 돌아가고, 화면에 그 사실을 알린다.
- 생성형 AI 없음. 외부 서비스는 파이어베이스뿐.

## 1. 구조 선택

| 안 | 장점 | 걸리는 점 | 판단 |
|---|---|---|---|
| **A. Realtime Database (RTDB)** | 웹소켓이라 바로바로 반영. 한 반 규모 데이터는 통째로 구독해도 가벼움. 무료 요금제로 충분 | 동시 접속 100개 제한(무료). 서울 지역 없음(싱가포르) | **추천** |
| B. Firestore | 서울 지역 있음. 질의가 유연 | 무료 하루 읽기 5만 회. 30명이 서로의 글을 실시간으로 받으면 읽기 수가 빨리 늘어남. 규칙이 더 복잡 | 보류 |
| C. 공유 링크 자체 저장소(db) | 따로 준비할 것 없음 | 학생이 모두 claude.ai 로그인 필요 | 제외 |
| D. 공유 링크 자체 실시간(room) | 준비 없음 | 저장이 안 됨(늦게 들어온 학생은 못 봄) | 제외 |
| E. 파이어베이스 호스팅에 사이트를 올리고 RTDB 사용 | 공유 링크의 보안 정책 걱정 없음 | 링크가 바뀜(claude.ai 링크 대신 web.app 주소). 다시 올리는 방법이 달라짐 | **0단계에서 A가 막히면 이쪽** |

## 2. 0단계: 가장 먼저 확인할 것 (스파이크)

공유 링크(아티팩트)는 claude.ai 안의 격리된 틀에서 돈다. 다음이 되는지 **실제 링크에서** 먼저 확인한다. 이 작업 환경은 외부 접속이 막혀 있어 여기서는 확인할 수 없다.

1. jsDelivr에서 파이어베이스 SDK 불러오기: `https://cdn.jsdelivr.net/npm/firebase@10.12.2/firebase-app-compat.js`, `firebase-auth-compat.js`, `firebase-database-compat.js` (파일이 있는 것은 확인함)
2. 익명 로그인(`identitytoolkit.googleapis.com`) 요청이 통과하는지
3. RTDB 웹소켓(`*.firebasedatabase.app`) 연결과 실시간 수신이 되는지
4. 로그인하지 않은 학생 기기에서도 1~3이 되는지
5. 요청을 보내는 쪽 주소(origin)가 무엇인지 → API 키 사용처 제한에 씀

방법: 문영일보와 **별도의 시험 링크**를 하나 만들어 "연결됨 / 막힘(어느 단계)"만 보여 준다. 교사 PC와 학생 기기 하나로 확인한다. 막히면 1번 표의 E안으로 간다.

## 3. 교사가 할 준비 (파이어베이스 콘솔, 약 20분)

1. Google 계정으로 파이어베이스 프로젝트 만들기(무료 Spark 요금제)
2. Authentication → 로그인 방법 → **익명** 사용
3. Realtime Database 만들기 → 위치 `asia-southeast1`(싱가포르) → 잠금 모드로 시작 → 아래 7번 규칙 붙여넣기
4. 프로젝트 설정 → 웹 앱 추가 → 설정값(apiKey, authDomain, databaseURL, projectId, appId) 복사
5. 교사 도구에 뜨는 "내 연결 번호"(익명 uid)를 콘솔에서 `/admins/<번호>: true` 로 한 번 등록
6. (권장) Google Cloud 콘솔에서 API 키 사용처를 0단계에서 확인한 주소로 제한

## 4. 설정값을 어디에 둘까 (작업노트: "키는 파일에 넣지 않음")

- 파이어베이스 웹 설정값의 apiKey는 비밀번호가 아니다. 앱을 알아보는 이름표에 가깝고, 실제 보호는 **보안 규칙**(7번)과 키 사용처 제한이 한다. 그래도 저장소(GitHub)에 남기지 않는다는 원칙은 지킬 수 있다.
- **추천:** 교사 도구 "실시간 연결"에 설정값을 붙여 넣으면, 턴 바꾸기와 같은 방식으로 페이지를 새 판으로 게시해 **공유 링크 안에만** 넣는다. 저장소의 `index.html`은 빈 값. `build_artifact.py --live` 가 턴처럼 이 값도 옮긴다.
- 다른 안: 파일에 넣기(간단하지만 원칙과 어긋남), 링크 뒤에 붙여 배포(claude.ai 링크가 그 부분을 틀 안으로 넘기는지 불확실).

## 5. 방(수업) 나누기

- 학번 앞 두 자리 = 학년반(예: 1444 → 14 = 1학년 4반)으로 본다. **학번 규칙 교사 확인 필요.**
- 교사 도구 "새 수업 열기": 반을 고르면 `/rooms/<방>` 을 만들고 `/current/<학년반>` 이 그 방을 가리키게 한다. 학생은 입장할 때 자기 학년반의 현재 방으로 들어간다.
- 지난 방은 지우지 않고 남긴다(디브리핑, 평가, 다음 해 예시). 반마다 방이 따로라 두 반이 같은 시간에 써도 섞이지 않는다.
- 턴도 방마다 따로(`meta.turn`). 지금의 "페이지 다시 게시" 턴 방식은 연결이 안 될 때만 쓰는 예비가 된다.

## 6. 데이터 구조 (RTDB)

```
/admins/<uid>: true                                   교사(콘솔에서 직접 등록)
/current/<학년반>: "<방>"                              지금 수업 중인 방
/rooms/<방>/
  meta: { owner, cls: "14", title, createdAt,
          turn: 0, turnAt: { "0": ms },               턴과 시작 시각
          open: true, slowSec: 0,                     댓글 멈춤, 느린 모드
          rx: { on, level, speed } }                  가상 반응 설정(지금 교사 도구 값)
  members/<uid>: { seat: "1444", nick, anonUsed, joinedAt, lastPostAt }
  names/<uid>: "1444홍길동"                           ← 교사가 이름 저장을 고를 때만. 교사만 읽음
  posts/<기사>/<글>: { uid, nick, anon, text,
          parent: "" | 시드 댓글 아이디 | 학생 글 아이디,   "" 이면 댓글, 아니면 답글
          turn, gameTs, at, v, n }                    쓴 턴, 게임 시각, 실제 시각, 반응 판정, 순번
  gone/<기사>/<글>: true                              본인 삭제
  votes/<기사>/<대상>/<uid>: 1 | -1                   대상 = 시드 댓글, 학생 글, 기사 자체는 "_article"
  reports/<기사>/<대상>/<uid>: { reason, detail, at }  교사만 읽음
  mod/<기사>/<대상>: { status: "blind"|"delete"|"dismiss", reason, at }
```

- 익명 글은 `nick` 을 빈 값으로 올린다(데이터를 열어 봐도 닉네임이 안 보이게). 교사는 `uid → members` 로 누군지 안다.
- 지금 브라우저 저장 키와의 대응: `comments:기사`·`replies:기사` → `posts`(parent로 구분), `creact:기사`·`vote:기사` → `votes`, `reports:기사` → `reports`, `moderation:기사` → `mod`, `anonUsed` → `members.anonUsed`, `turn`·`rx:turnAt` → `meta.turn`·`meta.turnAt`, `rx:on/level/speed` → `meta.rx`. `profile` 은 브라우저에 그대로 두고 서버에는 학번(과 선택 시 이름)만.

## 7. 보안 규칙 (초안, 콘솔 규칙 시뮬레이터로 검증 전)

RTDB 규칙은 위에서 준 읽기 권한을 아래에서 뺄 수 없다. 그래서 방 전체에 읽기를 주지 않고 칸마다 따로 준다.

```json
{
  "rules": {
    "admins": { ".read": false, ".write": false },
    "current": {
      ".read": "auth != null",
      "$cls": { ".write": "root.child('admins').child(auth.uid).exists()" }
    },
    "rooms": {
      "$room": {
        "meta": {
          ".read": "auth != null",
          ".write": "root.child('admins').child(auth.uid).exists()"
        },
        "members": {
          ".read": "auth != null",
          "$uid": {
            ".write": "auth.uid === $uid",
            ".validate": "newData.child('seat').isString() && newData.child('nick').isString() && newData.child('nick').val().length <= 12",
            "lastPostAt": { ".validate": "newData.val() === now" }
          }
        },
        "names": {
          ".read": "root.child('admins').child(auth.uid).exists()",
          "$uid": { ".write": "auth.uid === $uid", ".validate": "newData.isString() && newData.val().length <= 20" }
        },
        "posts": {
          ".read": "auth != null",
          "$aid": {
            "$pid": {
              ".write": "!data.exists() && auth != null && root.child('rooms').child($room).child('meta/open').val() === true && newData.parent().parent().parent().child('members').child(auth.uid).child('lastPostAt').val() === now && (!root.child('rooms').child($room).child('members').child(auth.uid).child('lastPostAt').exists() || now - root.child('rooms').child($room).child('members').child(auth.uid).child('lastPostAt').val() > 5000 + root.child('rooms').child($room).child('meta/slowSec').val() * 1000)",
              ".validate": "newData.child('uid').val() === auth.uid && newData.child('text').isString() && newData.child('text').val().length >= 1 && newData.child('text').val().length <= 400 && newData.child('at').val() === now"
            }
          }
        },
        "gone": {
          ".read": "auth != null",
          "$aid": { "$pid": { ".write": "root.child('rooms').child($room).child('posts').child($aid).child($pid).child('uid').val() === auth.uid" } }
        },
        "votes": {
          ".read": "auth != null",
          "$aid": { "$tid": { "$uid": {
            ".write": "auth.uid === $uid",
            ".validate": "newData.val() === 1 || newData.val() === -1"
          } } }
        },
        "reports": {
          ".read": "root.child('admins').child(auth.uid).exists()",
          "$aid": { "$tid": { "$uid": {
            ".write": "auth.uid === $uid && !data.exists()",
            ".validate": "newData.child('reason').isString() && newData.child('reason').val().length <= 20"
          } } }
        },
        "mod": {
          ".read": "auth != null",
          ".write": "root.child('admins').child(auth.uid).exists()"
        }
      }
    }
  }
}
```

- 글쓰기는 `posts` 와 `members/<나>/lastPostAt` 을 **한 번에(다중 경로 업데이트)** 써야만 통과한다. 그래서 5초(+느린 모드) 안에 다시 쓰면 서버가 막는다.
- 교사가 `meta.open` 을 끄면 서버에서 글쓰기가 막힌다(화면만 막는 것이 아님).
- 학생은 남의 글을 고치거나 지울 수 없고, 신고 내용과 이름은 읽을 수 없다.
- 금칙어는 지금처럼 화면에서 걸러 자동 신고한다. 화면 검사는 우회할 수 있으므로, 꼭 막아야 할 낱말 몇 개는 규칙 `.matches()` 로 서버에서도 막을 수 있다(교사가 목록 결정).

## 8. 화면 동작

- **입장:** 시작 화면(학번이름, 닉네임) → 익명 로그인 → `members` 등록 → `/current/<학년반>` 의 방으로 → `meta` 와 방 전체 `posts`, `votes`, `mod`, `gone` 구독. 한 반 글은 수백 개 수준이라 통째로 받는다(목록의 댓글 수, 작성자별 보기에 필요).
- **닉네임 겹침:** 같은 방에 같은 닉네임이 있으면 다른 닉네임을 쓰게 한다(친구 사칭 방지).
- **합치기:** 시드 댓글 + 방의 학생 글을 합쳐 지금 그리는 함수에 그대로 넘긴다. 게임 시각(`postStamp`)은 합친 데이터 기준으로 계산하고, 같으면 실제 시각(`at`) 순.
- **추천 수:** 시드 값(`grown` 적용) + 실시간 표. 학생 글도 추천이 많으면 BEST에 오른다(몰려가기가 교실 안에서 보임).
- **턴:** `meta.turn` 이 바뀌면 새로고침 없이 다시 그린다. 쓰던 댓글과 답글이 지워지지 않는다.
- **교사 도구:** 반 전체 신고 접수함(실시간), 블라인드/삭제/기각 즉시 반영, 댓글 멈춤, 느린 모드(10초/30초), 수업 기록 내보내기.
- **가상 반응:** 시드 계산(기사, 턴, 판정, 출석번호, 순번)이라 모든 화면에서 같은 값이 나온다. 그래서 실시간 모드에서도 그대로 보여 줄 수 있다. 다만 진짜 반 친구 반응과 섞이면 학생이 둘을 구분하지 못할 수 있음 → 교사 결정 3.
- **연결 실패:** 6초 안에 연결이 안 되면 "실시간 연결 안 됨: 이 화면에만 저장됩니다" 띠를 띄우고 지금 방식으로 돈다. 나중에 연결돼도 그동안 쓴 글을 올리지는 않는다(단순하게).

## 9. 수업 운영에서 생길 문제와 대책

| 문제 | 대책 |
|---|---|
| 실제 반 친구를 겨냥한 댓글, 실명 언급 | 교사 실시간 블라인드, 댓글 멈춤. 시작 전 약속(가상 인물에 대해서만). 기록이 남는다는 것을 미리 알림 |
| 도배, 장난 글 | 서버 5초 제한 + 느린 모드. 금칙어 자동 신고 |
| 닉네임 사칭 | 방 안 닉네임 중복 금지. 교사는 학번으로 확인 |
| 개인정보(미성년, 해외 서버) | 서버에는 학번과 닉네임만(추천). 이름은 교사 브라우저에만. 학교 개인정보 지침 확인 |
| 동시 접속 100개(무료) | 한 반 35명은 여유. 세 반이 동시에 쓰면 넘을 수 있음 → 그때는 종량제(Blaze, 이 규모면 사실상 0원)로 |
| 평가 윤리 | 루머에 동조한 글 자체를 감점하면 학생이 솔직하게 반응하지 않음. 평가는 **디브리핑에서 자기 댓글을 근거로 판단 과정을 돌아보는 것**(출처를 물었나, 언제 생각이 바뀌었나)에 둔다 |

**수업 기록 내보내기(평가, 디브리핑용):** 학번, 닉네임, 기사, 턴, 게임 시각, 글, 받은 추천과 반대, 답글 수, 신고 여부, 처리 결과를 CSV로. 수업 직후 "내가 쓴 댓글 다시 보기" 활동에 바로 쓸 수 있다.

## 10. 작업 순서

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 0 | 시험 링크로 연결 확인(2번) + 교사 콘솔 준비(3번) | 교사 PC + 학생 기기 1대 |
| 1 | 댓글, 답글, 추천 실시간 / 턴 실시간 / 방 / 연결 실패 대비 | 여기서는 가짜 저장소로 자동 시험. 실제 연결은 교사 기기 2~3대 |
| 2 | 신고와 블라인드 실시간, 댓글 멈춤, 느린 모드, 내보내기 | 한 반 시범 수업 |
| 3 | 가상 반응과 섞는 방식, 게임 역할(분석관, 수사관, 당사자, 네티즌) 연결 | 시범 뒤 결정 |

- `store` 객체를 바꾸는 것만으로는 안 된다. 지금은 "읽을 때 가져오기"인데 실시간은 "바뀌면 알려 주기"라서, 저장소 층(`remote`)을 새로 두고 그리는 쪽이 구독 결과를 받게 바꾼다.
- 이 작업 환경은 파이어베이스 서버에 접속하지 못할 가능성이 높다(jsDelivr도 막힘). 그래서 실제 서버 시험은 교사 기기에서 해야 한다.

## 11. 교사 결정 필요

1. **서버에 올릴 신원:** 학번만(추천, 스킬 규칙 "좌석 번호만"과 맞음) / 학번이름(교사만 읽기)
2. **설정값 위치:** 공유 링크 안에만(추천) / 파일에 넣기
3. **가상 반응:** 교사가 켜고 끔(추천, 기본 켬) / 실시간 수업에서는 끔 / 그대로
4. **반 구분:** 학번 앞 두 자리 자동(추천, 학번 규칙 확인 필요) / 교사가 수업 코드 배포
5. **시작 범위:** 0~1단계를 먼저 하고 한 반 시범(추천) / 2단계까지 한 번에
